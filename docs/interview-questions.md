# 引っ越し業者ヒアリング 質問リスト

目的: シミュレータが置いている**人間モデルの仮定の答え合わせ**と、**現場で実際に何が原因で詰まるのか**の把握。
質問は「回答をそのままプログラムの定数・制約に変換できるか」を基準に選ぶ（数字で答えられる形で聞く）。

シミュレータ側の仮定（2026-09-08時点、`phase2/phase2_lstair.py`）:

| 仮定 | 値 | 対応する定数 |
|---|---|---|
| 家具の傾きの上限 | 55度 | `MAX_TILT_DEG` |
| 持ち手の高さ（足元から） | 10〜190cm | `REACH_MIN` / `REACH_MAX` |
| 体の占有 | 直径40cm・身長170cmの円柱（膝下35cmは無視） | `HUMAN_R` / `LEG_CLEAR` |
| 持ち手と体の距離 | 30cm | `CARRY_ARM` |
| 検証シナリオの判定 | 幅90cmのL字階段で、200×50×65cmの家具は2人だと通らない。長さ162cmまでなら通る | `results/lstair_result.json` |

---

## 1. 前提の答え合わせ（数字で聞く）

- タンスや冷蔵庫を階段で運ぶとき、**どこまで傾けますか？** 完全に立てる（90度）ことはありますか？ 家具の種類（重さ・持ち手の有無）でどう変わりますか？
  → `MAX_TILT_DEG`（55度）の検証。家具種別ごとに値を分ける必要があるかの判断
- 持ち手の位置が**低すぎて／高すぎて**持てない、という状況はありますか？ だいたい床から何cm〜何cmなら持てますか？
  → `REACH_MIN`/`REACH_MAX`（10〜190cm）の検証
- 2人で運ぶとき、**前後の人はどれくらい家具から離れて**持ちますか？ 体を横にずらして持つことはありますか？
  → `CARRY_ARM`（30cm）と`SIDE_OFFSETS`の検証

## 2. 踊り場での回し方（動きを聞く）

- L字階段の踊り場で長い家具を回すとき、**どういう動きをしますか？**（立てて回す／斜めに振る／角に鼻先を突っ込んで回す 等）
  → シミュレータは「斜め50度で先端を上フライトの吹き抜けに突っ込みながら回す」動きを自力で見つけた。**これは実際に使うテクニックか？**
- 回している最中に一度**手を持ち替える**ことはありますか？ それは「よくある」レベルですか？
  → 持ち替え（multi-modal planning）をスコープ外にしている判断の妥当性確認
- 踊り場に**手すりや照明**があるとき、どれくらい効きますか？
  → 環境モデルに手すりを足す優先度の判断

## 3. 現場の判断基準（見積もりの実態）

- 下見のとき、階段まわりでは**何をどこまで測りますか？** 測らずに「見て判断」する部分はどこですか？
- 「この階段なら**長さ何cmまでの家具**なら大丈夫」という経験則はありますか？ 幅90cm前後の普通の戸建てL字階段だと何cmくらいですか？
  → シミュレータの答え（162cm）との突き合わせ。**これが一番聞きたい質問**
- 「入るか際どい」と思ったとき、最終的に**誰が・いつ・どうやって**通せる/通せないを判断しますか？ 判断が外れたことはありますか？

## 4. 失敗事例（詰まりの原因の分布）

- 実際に「通ると思ったのに通らなかった」事例を教えてください。**原因はどこでしたか？**（幅／長さ／天井／踊り場の回転／人が立つ場所がない／その他）
  → 「人の分のスペースが原因」がどれくらいの割合かは、このプロジェクトの主張の核心
- そうなったとき**どうしましたか？**（吊り上げ／分解／返品／窓から 等）クレーン切替の頻度と、お客さんの追加負担はどれくらいですか？

## 5. 分解・その他

- 搬入前に**脚を外す・分解する**のはどれくらいの頻度ですか？ 分解できるかは事前にどう確認しますか？
  → 分解状態を別剛体として扱う設計（CLAUDE.md）の入力になる
- 逆に「これはアプリで事前に分かっていたら助かった」という情報はありますか？
  → 機能の優先順位づけ

## 聞き方のメモ

- 数字を聞くときは「だいたいで」「範囲で」よいと伝える（正確さより、モデルの仮定と桁が合っているかが知りたい）
- 動きの質問は、その場で**段ボール等を持って再現してもらう**のが一番早い（可能なら動画を撮らせてもらう）
- 最後にシミュレータの図（比較PNG・GIF）を見せて「この詰まり方はリアルか？」を聞く — モデル全体の妥当性への一言コメントが得られる
