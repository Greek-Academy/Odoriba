# BACKLOG — 自律実行の作業キュー

スケジュール実行されるクラウドエージェント（および人間）が上から順に消化する作業キュー。

## 運用ルール（エージェントはここに従うこと）

- **1回の実行で消化するのは、未完了(`[ ]`)の最上位タスク1つだけ**
- 作業は CLAUDE.md の規約に従う: develop から `feature/<説明>` を切る／Conventional Commits／日本語コメント／細かいコミット粒度／`merge --no-ff` で develop へ統合して push
- 完了したら該当行を `[x]` にし、末尾に `(YYYY-MM-DD, ブランチ名)` を追記して、その変更もコミットに含める
- タスクが技術的に不可能・前提が壊れていると判明した場合は `[!]` にして理由を1行書き、次のタスクには進まない（人間の判断待ち）
- 探索（RRT）を回す場合は `--max-iter` を絞った動作確認をしてから本番実行する

## キュー

- [ ] **階段の段まで写ったスキャンで、1階から2階までを判定する**: 撮り直しは人間の作業（階段を一段ずつ上りながら踏み面にカメラを向ける）。今の家のスキャン（2026-10-06）は段の上面が写っておらず、1階から踊り場まで「歩ける床がつながっていない」になる。撮り直したスキャンが届いたら `scan_picker.py` で玄関→2階の部屋を判定し、結果を HANDOFF に記録する
- [ ] **スキャンの寸法とメジャー実測の突き合わせ**: 実測は人間の作業（スキャンと同じ範囲を測る。stair1 は2フライト分=高さ約5.1mを捉えており、1フライト分の仮実測235cmとは範囲が違った）。実測値が届いたら、スキャン空間から測った幅・蹴上げ・踏み面・天井高と比べ、5cmを超える誤差があれば手入力に切り替える（PRD の Open Questions のゲート）
- [ ] **螺旋・S字階段の環境**: 回り階段で入れた回転した直方体で組む。回り階段・L字・折り返しと同じく、家具単体と運搬者2人の掃引、結果JSONを出す
- [ ] **大きなスキャンでの空間作成の高速化**: 家のスキャン（8.6×8.1m・34万面）で `ScanSpace` の作成に約1分かかる。距離場の作成を、出発点から届く範囲だけに絞るなどで短くする
- [x] **実スキャンの取り込み仕上げ**: 水密化をやめ、スキャンのメッシュをそのまま環境にする方式（`scan_space.py`・`scan_plan.py`）で置き換えた。内外は出発点からの塗りつぶしで決め、出発点・目的地は自動提案とブラウザでの指定（`scan_picker.py`）に対応。残った撮り直し・実測は上の2つに分けた (2026-10-06, feature/scan-space-planning / feature/scan-endpoint-picker)
- [x] **折り返し（U字）階段の環境**: 踊り場で180度折り返す、日本の戸建てで最も多い形。軸平行の直方体だけで組めるため、既存のオラクル・RRTに歩行面関数を差し替えて対応（`phase2_ustair.py`）。家具単体PASS・余裕8.8cm / 運搬者2人は踊り場全域で不足、最大29cm (2026-09-29, feature/u-turn-staircase)
- [x] **螺旋階段・回り階段の環境**: 回転した直方体で環境を組めるようにし、コーナー踏み面（回り階段）か螺旋をデモ化する。`horizontal_clearance_points` のAABB前提もこのとき拡張する。回り階段(30度x3段)を `phase2_winder.py` で実装。家具単体PASS・余裕5.3cm / 運搬者2人は角で29cm不足（L字・折り返しと同値。原因は傾き上限55度で、人体ではない — 要調査）。螺旋は未着手 (2026-10-06, feature/winder-staircase)
- [x] **メッシュ→SDF受け口**: `build_lstairs` の環境をメッシュ（OBJ/PLY）として書き出し、trimesh で読み込んで点→メッシュ距離で衝突判定する `validator` を作り、既存の直方体方式と判定結果が一致することを確認する（iPhone LiDAR スキャンの受け入れ準備。open3d が入らない環境では trimesh のみで可） (2026-09-08, feature/mesh-sdf-input)
